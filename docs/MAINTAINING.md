# 维护说明

给真正住在中国大陆的人讲清楚：接了海外的活、做的内容有了收入、在海外平台开了网店，怎么选一条正规的路把钱收回来，费用怎么算，每人每年 5 万美元的额度管什么，钱怎么换成人民币到自己的银行卡上。说人话，第一次收海外的钱也能看懂。
五块内容：新手入门（三课）、完整教程（按顺序 0–5 步）、How-to（具体怎么做）、Wiki（这是什么）、常见问题。

**本站是非官方学习站**，和 PayPal、Wise、Payoneer、万里汇（WorldFirst）或任何银行都没有关系，**也不是法律或税务建议**。页脚、常见问题和 README 都要写明这两点。费用和规则以各家自己的页面和读者的开户银行为准，外汇规定以国家外汇管理局为准。不用任何一家的标志和配色，不写成它们的口吻。

- 站点骨架沿用 xxd-saily（Saily 新手教程站，`../xxd-saily`，它又是从 Grok Bot 新手教程站搭出来的）：同样的外壳、组件、搜索和写作规矩。Saily 那边的帮助中心同步脚本（`sync-docs`）这里没有：这个题目的资料来自很多家的网页和外汇局的规定，抓取工具在 `docs/sources/tools/`。
- 界面用 xxd-ui-kit（`public/xxd/` 里自带一份，不走 CDN）。
- **只有中文和英文。** 读者住在中国大陆，中文在根路径；英文在 `/en/` 下，给想对照原文、或者要把页面发给海外客户看的人。不加别的语言。两种语言 slug 相同，顶栏的语言菜单切到对应页。改了一篇中文，**同一次提交里把英文版也改了**：
  - 正文：`src/pages/en/start/`、`src/pages/en/guide/`、`src/pages/en/howto/`（MDX，路径多一层 `../`；站内链接加 `/en`；`<Term k="中文键" />` 照原样，英文名在 `nav.js` 的 `GLOSSARY[k].en`）。
  - 数据：`nav.js` 各条目的 `en: {}`；`wiki.en.js`、`faq.en.js`（按 slug 叠加，结构和条数要和中文一致）；界面文字在各组件和 `views/` 里的 zh / en 两份。
  - 强调：每页最多一处 `<mark>`（这页最要紧的一句），`<u>` 只给照做会出错的坑；英文页放在对应的那句上。
  - `node scripts/check-i18n.mjs` 查两边对不对得上（缺页、多页、frontmatter、复制块 id、图示、`<mark>`、站内链接的语言、Wiki 和常见问题的条数）。

## 写作规矩（硬规矩）

- **只讲正规的路。** 本站只讲用你自己的身份、真实地址和自己名下的账户收钱、结汇。下面这些不教，网友帖子里的这类步骤一律不搬进来，教程里有人这样写也不复述细节：
  - 用不是你的地址或身份开海外账户：美区 PayPal、港区 PayPal、香港 Stripe，转运地址、借来的地址都算。
  - 拆分金额，让每一笔停在某个数下面。
  - 借用别人的额度、身份证或账户（包括让家人以外的人代办），或者用别人的账户收你的钱。
  - 把汇款用途、交易性质写成不是真的。
  - 用加密货币换成人民币（交易所、C2C、OTC 商家都算），也不提地下钱庄、「对敲」的办法。
  - 推荐码、邀请链接、返利链接，作者自己的也不放。

  要讲为什么不行，就引规定本身，附链接：《个人外汇管理办法》第七条（不得分拆、不得用虚假凭证）、《经常项目外汇业务指引》第六十二条（借用额度列入关注名单）、第五十七条（购汇申请如实填写）、第六十一条（只有近亲属能代办）、银发〔2021〕237号（虚拟货币），各家协议里不许用别人信息开户的条款。出处都在 `docs/sources/README.md` 第 3 节和第 2 节。
- **不是法律或税务建议。** 本站不讲个人所得税怎么交（资料包没有研究这件事）。碰到税，一句话带过：「这和税有关，本站不讲，问当地税务机关或专业人士。」碰到「我这笔收入算哪一类」，照指引第六十八条说：由办理的银行审核决定，本站不替读者归类。
- **每个费用和限额都带「截至」日期和那一页的链接。** 写法：「截至 2026-11-19，PayPal 的商家费用页写的是……（[费用页](链接)）」。页面自己写了「最近更新」日期的，两个日期都写。讲到底要扣多少，按段列出公式（收款费、换汇费、提现费、银行的手续费），不给一个「综合费率」。促销价写明起止日期，并写上原价。
- **说清楚是哪一种 PayPal 账户。** 现在中国大陆有两套：贝宝支付（北京）有限公司的新账户（`paypal.cn`，个人卖家开的是「个人类别的企业用户」）和 PayPal Pte. Ltd. 的老账户（`paypal.com/c2`）。两套的费用、提现方式、能不能收货款都不一样。只有一句话对两套都成立时，才只写「PayPal」。
- **5 万美元是便利化额度，不是上限。** 写到额度，就照外汇局的说法讲清楚这一点（实施细则第二条、指引第五十四至五十六条、外汇局厦门分局的提示），不写「每年最多只能换 5 万美元」这类话。
- **还没确认的事，照还没确认写**，并告诉读者去问服务商或开户银行（见上面「资料来源」）。
- **网友的帖子**只当作标明了的个人经验：写「有网友在 X 上分享」，附原帖链接，不替他补充、不评价他本人。`README.md` 第 4 节判为越线的帖子（@TaoRay、@DtDt666、@moranweb3、@aladdin_im、@victorhan2012）**一律不链接**，也不复述越线的那部分；@noahduck283 的「Wise 全网最全使用指南」里有拆分和借地址的做法，也不链接。要举「不该照做」的例子，就不点名地讲做法，再引规定。
- **界面上的按钮和菜单名，照官方页面上的字写，加粗。** 中文页：有中文页面的（`paypal.cn`、Payoneer 的简体中文页、万里汇），照它的中文写；只有英文的（Wise、Stripe），写英文，括号里给中文意思。英文页照英文写。
- 平台的提示、收到的邮件，用 `Reply` 组件，标题写「示意」，不冒充真实记录。截图和示意里的账号、卡号、身份证号、邮箱、余额、交易号一律换成示例，名字也换掉。
- 中文页和 `/en/` 下的英文页一起改，讲的事实和结构保持一致。
- 第一次出现的站内术语用 `Term` 包起来，悬停有一句解释。
- MDX 正文里不能出现裸的 `<`、`{`、`}`：占位符写在代码里，比如 `` `<你的银行卡号>` ``。

## 怎么写：像一个懂行的朋友，坐在旁边讲给你听

2026-11-19 的读者反馈（来自姊妹站 Grok Bot 新手教程，这套写法从那边沿用过来）：教程学起来累，很多话要「过一遍脑子」才懂，读着拗口。原因出在我们自己定的规矩上：一句不超过 30 个字、一句只讲一个意思、每一步都放一个「你应该看到」的框。句子被切成了电报，「因为」「所以」「其实」这些把意思连起来的词都被删了，读者只好自己去补。现在改成下面这套写法，参照凯文·凯利（Kevin Kelly）那种「抓住一个核心，用一个画面讲透」的写法，也合教育心理学里几条站得住的发现：对话的口吻比说明书的口吻更好学（Mayer 的个性化原则），故事比条目好记，意思连贯的长句比切碎的短句更省力。

1. **一页一个核心。** 开头几句就把它说出来，最好落在读者自己的处境上（「你是不是也……」）。这一句用 `<mark>` 标出来，全页只这一处。
2. **先讲画面，再讲方法。** 用收钱时真会遇到的事讲成小故事：海外客户说用 PayPal 付你，你却不知道国内能开哪种账户；一笔 100 美元的付款，到卡上只剩九十几块，不知道钱去了哪；年底收入快到 5 万美元，心里发慌；账户突然被限制，余额提不出来。道理放在故事后面，一两句就够。
3. **让句子连起来。** 该用「因为」「所以」「可是」「其实」「比如」「于是」就用。长句短句交替，不机械地拆句。写完念出声，哪里卡住就改哪里。
4. **像说话，不像说明书。** 用「你」，用平常的口语。避开公文腔和翻译腔：进行、基于、用于、对……进行、以……的方式、相关、该（当「这个」用）。也别喊口号、别装熟：正文里不写「超简单」「爽翻」「赋能」，具体说它做了什么、替你省了什么。
5. **段与段之间有过渡。** 读者应该一直知道「为什么现在讲这个」。
6. **格式克制。** 列表只放真正并列的几样东西；加粗只给关键的几个字；Callout 一页一两个，只放真有用的提醒。「你应该看到」只用在界面会变化、读者需要确认自己没走错的地方，比如实名认证通过、绑好银行卡、提交了结汇申请那几步。
7. **新词顺手解释。** 像朋友那样一句带过（「结汇，就是把收到的外币换成人民币」），不要一段里堆好几个新词。
8. **收个尾。** 页末一两句：刚才学会了什么，下一步去哪。
9. **要读者照抄的话像平时说话。** 比如去银行柜台或者写给客服的一段说明，写成完整、自然的话，不用填空模板腔：「我在海外平台上接设计的活，这笔是客户付的服务费，合同和付款记录我都带来了，想把这笔美元结成人民币。」
10. **英文页同理。** Conversational, warm and plain. Contractions are fine. Vary sentence length. No corporate words (leverage, utilize, seamless, empower).

每类页面的样子：

- **新手入门三课**（`src/pages/start/`，数据在 `nav.js` 的 `LESSONS`）：给第一次从海外收钱、还没开过任何收款账户的人。开头一个小场景，然后讲清这一课的那件事；只给一条路，别的情况放进页尾「不对怎么办」，按读者遇到的现象写（「客户说只能用银行转账」）；不出现没解释过的词（SWIFT 代码、中间行、关注名单这类不进新手页，除非这一课就是讲它）；说清楚三课之外的都是「遇到了再查」。
- **完整教程**（`guide/`）：一个核心想法，配一个收钱时的例子，再把要点的操作讲清楚，最后「卡住了？」。
- **How-to**：一件具体的事。开头一句说做完你会得到什么，然后按「什么时候会遇到、怎么做、做完怎么确认」讲下去，写成连贯的话，不是几个填空。
- **Wiki**：保留「一句话 → 打个比方 → 放到你身上 → 常见误区」的结构，每一块都用说话的口吻写。

## 正文里的图示（`<Fig id="…" />`）

一张图讲清一个关系，放在最需要的那一节：两条路的对比、几步的顺序、钱经过哪几段、由强到弱。不是每节都配；同一页最多两张。

- **数据和文字**在 `src/data/figs.js`：每张图一个 id，`type` 选画法（compare、term、folder、anatomy、stack、flow、night、ladder、fan、tree），`base` 放和语言无关的部分（图标、哪一步要你动手），`zh` / `en` 放文字。现在一张都还没有；每种画法要哪些字段，看 `Fig.astro` 里对应的那段。
- **画法**在 `src/components/Fig.astro`，样式在 `public/site.css` 的「图示」一节。全部是 HTML + CSS：颜色、圆角用令牌，跟着亮暗、直角圆角、主色走；字能换行，正文栏窄了自动竖排（容器查询）。
- **动画**：进入视野后一步步亮起来，放两遍停在完整的样子，图下面出「再看一遍」。只动 opacity / transform；系统设了减少动效、或者没有脚本时直接显示完整的图。
- **图里的字**：一格一件事，短。不抄正文整句，也不喊卖点。图里的费用数字和正文一样要有出处，日期写在正文里。界面上的按钮名照真实界面写，说明文字才翻译。
- **新加一张**：先在 `figs.js` 写数据，再在中文页、`/en/` 页同一位置放 `<Fig id="…" />` 并 `import Fig`；`npm run build` 后亮色、暗色、手机宽度各看一眼。

## 分享大图和标志

- 分享大图：样子和文字都在 `tools/og.html`（一张 HTML 海报，`?lang=zh` / `?lang=en`）。`python3 tools/build_og.py` 用 Chrome 截图，2 倍清晰度（2560×1280），写出 `public/og.png`（中文页分享用）、`public/og-en.png`（英文页分享用），再复制一份到 `assets/social.png`、`assets/en/social.png`（README 头图）。`Site.astro` 只在两张 og 图存在时才输出 `og:image`。改完两张都看一眼：字有没有互相压住、顶到边。GitHub 仓库的 Social preview 用英文那张，要在仓库 Settings → General 手动上传。
- 本站标志（`Site.astro` 里的 `site-mark` 和 `public/favicon.svg`）是一枚墨色的硬币，中间一个往左下指的箭头（钱进来），和小小东其他站同一套笔法：实心的形状，挖出来的细节，箭头是直角转折。故意不像任何一家收款平台或银行的图标，本站是非官方的。
- 配色要干净通透：画布接近白（`#FAFAF8`，一圈 `#E9E7E4` 淡边），卡片纯白，线和次要文字用 UI Kit 的 `--line`、`--muted`，浅色块用去掉灰调的浅色。不要灰米色底和偏棕的阴影。不用任何一家的标志和配色。
